# New linear codes over GF(4)

Thirteen linear codes over GF(4) whose minimum distance is one or two above the lower bound in
Markus Grassl's tables of linear codes at [codetables.de](https://www.codetables.de), as read on
2026-11-05. Together they raise 29 cells of the table, ten of them by two. They were sent to the
table's maintainer on 2026-11-05 and are not in the table yet.

## How the codes are built

GF(4) = {0, 1, w, w^2} with w^2 = w + 1. In the files a polynomial is written as its string of
coefficients, constant term first, with 2 standing for w and 3 for w^2.

**Quasi-cyclic codes.** Take m, a divisor g(x) of x^m - 1, and polynomials r_1(x) = 1, r_2(x),
..., r_l(x). The 1-generator quasi-cyclic code generated by (g r_1, ..., g r_l) modulo x^m - 1
has the generator matrix whose row i, for i = 0, ..., k - 1 with k = m - deg g, is
x^i (g r_1, ..., g r_l) reduced modulo x^m - 1, each of the l blocks written as its m
coefficients, constant term first. Its length is l m and its dimension k. Three of the codes are
of this kind: [182,13,114], [189,14,116] and [204,9,140].

**Construction X.** The other ten start from such a code C1, with minimum distance d1, and its
subcode C2 generated by (g f r_1, ..., g f r_l), where f(x) divides (x^m - 1)/g(x). C2 has
dimension k - deg f and a larger minimum distance d2. An auxiliary code with minimum distance
dA and a generator matrix A of deg f rows supplies a tail: row i of C1 is extended by c A, where
c holds the deg f coefficients of x^i mod f(x), constant term first. The words of C2 get a zero
tail and every other word of C1 a nonzero one, so the new code has minimum distance at least
min(d2, d1 + dA). The auxiliary codes used are the [2,1,2] and [3,1,3] repetition codes, the
[4,2,3] extended Reed-Solomon code, the [5,2,4] simplex code and the [6,3,4] hexacode.

The values of m, g, f, the r_j and A for each code are in the comments of its file.

## How they were checked

The minimum distance and the number of minimum-weight words of every code were computed exactly
with two independent programs, one that enumerates every codeword in Gray-code order and one
that implements the Brouwer-Zimmermann algorithm, and confirmed by a third, separately written
program that counts the weight of every codeword. Every generator matrix was also rebuilt from
its construction alone, as described above. Before the codes were sent, the table's cell pages
and updates log, MinT, Chen's database of quasi-twisted codes, arXiv, GitHub and Zenodo were
searched for these parameters (2026-11-04 and 2026-11-05), and all 29 cells were read again on
the live table on 2026-11-05.

To check a code with Magma, run for example

```sh
magma codes/GF4_209_10_140.magma
```

It builds the code and prints its dimension and minimum distance; the expected values are in the
comment just above the file's last line.

## How this work was done

The codes were found and checked by AI agents (Claude, by Anthropic), which wrote and ran the
search and verification programs under the author's direction. Those programs are not part of
this release.
